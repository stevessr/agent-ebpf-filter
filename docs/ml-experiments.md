# ML 实验框架使用指南

本文档面向使用本仓库中机器学习实验框架的开发者与研究者，说明如何快速启动实验、配置批量任务、解读结果，以及如何扩展自定义实验。

## 1. 快速开始

### 1.1 你会得到什么

实验框架主要用于：

- 对不同模型与参数组合做批量评估
- 记录训练、验证、推理与策略效果指标
- 生成可复现的 CSV、JSON、SVG、HTML 报告
- 对比不同数据集、不同模型族、不同超参数的表现

### 1.2 基本工作流

1. 准备数据集与标签
2. 选择实验模式与模型族
3. 运行批量 sweep
4. 查看 `coverage.json`、`results.csv`、`best.json`、`index.html`
5. 根据验证准确率、ALLOW 通过率、训练耗时和推理吞吐做决策

### 1.3 常用运行方式

从仓库根目录执行：

```bash
rtk make runtime-benchmark
```

如果需要手动运行底层测试，也可以直接执行：

```bash
rtk bash -lc 'cd backend && RUNTIME_REPLAY_OUT=../reports/runtime-replay-manual/summary.json go test ./... -run TestRuntimeReplaySuite -count=1 -v'
```

> 注：上面的命令更偏向离线回放与运行时回归检查；机器学习 sweep 通常会生成位于 `reports/ml-sweep-*/` 的实验产物。

### 1.4 输出目录说明

实验结果通常会写入类似目录：

- `reports/ml-sweep-YYYYMMDD-HHMMSS/`
- `reports/ml-sweep-random-forest-1000/`
- `reports/ml-sweep-extra-trees-1000/`

常见文件包括：

- `coverage.json`：覆盖率与通过/失败清单，通常是最权威的完整性依据
- `results.csv`：逐行实验结果表
- `best.json`：当前最佳配置摘要
- `stability-summary.csv`：稳定性统计
- `index.html`：可视化汇总页面

## 2. 批量实验配置

### 2.1 批量实验的核心概念

一个批量实验通常由以下部分组成：

- **数据集**：例如全量数据、标签均衡数据，或者其他子集
- **模型 ID**：如随机森林、Extra Trees、Logistic、SVM、KNN 等
- **参数网格**：例如树数量、最大深度、学习率、迭代次数等
- **重复次数**：用于观察稳定性
- **并行 worker 数**：提升扫描速度
- **模式**：如 `comprehensive`、`full` 或其他框架支持的模式

### 2.2 推荐的批量配置原则

建议按以下顺序扩展实验空间：

1. 先做小网格，确认流程和数据管线正常
2. 再扩大参数范围，寻找候选最优模型
3. 最后对候选最优配置做稳定性重复实验

### 2.3 常见配置维度

#### 数据集

- `all`：全量样本
- `label-balanced`：类别均衡样本

建议同时跑全量集和均衡集，避免只在单一分布下得出结论。

#### 模型族

常见模型族包括：

- 树模型：`random_forest`、`extra_trees`
- 线性模型：`logistic`、`svm`、`ridge`、`perceptron`、`passive_aggressive`
- 邻近/原型模型：`knn`、`nearest_centroid`
- 概率与集成模型：`naive_bayes`、`adaboost`、`ensemble`

#### 超参数

常见可调参数包括：

- `trees`：树的数量
- `depth`：树深度
- `leaf`：叶子最小样本数
- `lr`：学习率
- `iter`：迭代次数
- `alpha`：正则强度
- `k`：KNN 邻居数

### 2.4 1000 点矩阵式实验

如果你要做完整覆盖式扫参，可使用类似以下策略：

- 选择多个数据集
- 对每个模型 ID 扫描所有可调参数
- 每个数值参数取足够多的采样点
- 用 `coverage.json` 检查是否达到目标覆盖

文档中已有一个完整案例：

- `--mode comprehensive`
- `--datasets all,label-balanced`
- `--points-per-param 1000`
- `--workers 8`
- `--repeats 1`
- `--stability-top 1`

该类实验适合做大规模对比，但耗时较长。

### 2.5 批量实验建议模板

建议按下面顺序组织实验目录：

- `reports/ml-sweep-<timestamp>/`：一次完整 sweep
- `reports/ml-sweep-<family>-1000/`：某个模型族的专项扫参
- `reports/ml-sweep-<family>-stable/`：稳定性复测结果

同时建议保留：

- 原始 `results.csv`
- 最优 `best.json`
- 生成时的参数命令
- 运行环境信息

这样后续复现实验时更方便。

## 3. 结果解读

### 3.1 先看哪些指标

建议不要只看准确率，而是至少同时看四类指标：

- **验证准确率**：模型分类是否足够准确
- **ALLOW 通过率**：正确请求是否被误拦截
- **训练耗时**：训练是否可接受
- **推理吞吐**：上线后是否足够快

如果任务是安全策略或拦截决策类问题，`ALLOW` 通过率往往和准确率同样重要。

### 3.2 如何判断“最好”的模型

不要直接把最高准确率当成最终答案。更合理的判断顺序是：

1. 先排除明显不稳定或效果差的模型
2. 再比较 holdout-comparable 模型
3. 再在准确率接近时比较 ALLOW 通过率
4. 最后比较训练/推理成本

### 3.3 Holdout-comparable 与 optimistic 的区别

文档中把模型分成两类：

- **holdout-comparable**：如 `random_forest`、`extra_trees`、`logistic`、`svm`、`perceptron`、`passive_aggressive`、`ensemble`
- **train-set-based / optimistic**：如 `knn`、`ridge`、`adaboost`、`naive_bayes`

前者更适合作为主决策依据，后者更适合作为参考和回归检查。

### 3.4 如何读 `best.json`

`best.json` 通常给出当前实验空间下的最佳配置摘要。阅读时重点看：

- 模型 ID
- 参数组合
- 训练与验证指标
- 是否达到预期阈值
- 是否在重复实验中保持稳定

### 3.5 如何读 `coverage.json`

`coverage.json` 是判断实验是否“跑全了”的首要文件。重点关注：

- 是否所有预期模型都已覆盖
- 是否所有参数点都已执行
- 是否存在失败或跳过项
- 是否有未覆盖的数据集组合

### 3.6 结果解读示例

如果你看到：

- 某个模型准确率很高，但 ALLOW 通过率低
- 另一个模型准确率略低，但通过率更好且更快

那通常后者更适合实际部署。

如果某个模型在单次 sweep 中表现极强，但重复实验波动大，则更适合视作候选，而不是最终基线。

### 3.7 常见结论模式

一般会出现以下几类结论：

- **树模型最稳**：在非线性、类别偏斜数据中常常表现最好
- **轻量线性模型可作为强基线**：在低数据量或可分性较强场景中有竞争力
- **邻近类模型可能很快但不一定可部署**：需要区分训练集记忆与真实泛化
- **集成模型常提升上限，但可能牺牲速度**

## 4. 自定义实验扩展

### 4.1 何时需要扩展

如果你遇到以下需求，就应该自定义实验：

- 新增模型族
- 加入新的超参数
- 支持新的数据集切分
- 加入额外评估指标
- 生成新的报告视图
- 做稳定性、消融或对照实验

### 4.2 扩展一个新模型族

建议按以下步骤做：

1. 在模型注册表中增加模型 ID
2. 定义基础算法与默认参数
3. 给 UI / 报告层补充显示名和说明
4. 在 sweep 配置中加入参数网格
5. 在结果汇总逻辑中补齐指标字段

### 4.3 扩展一个新超参数

新增参数时，建议同时处理：

- 默认值
- 参数范围
- 结果序列化
- HTML 图表展示
- `coverage.json` 覆盖检查

这样才能保证新参数不会只跑了实验，却没有进入结果分析链路。

### 4.4 扩展一个新数据集

新增数据集一般要做这些事：

- 统一标签定义
- 检查类别分布
- 决定是否需要均衡子集
- 决定是否要做敏感信息清洗
- 确认导入后是否进入训练存储

如果数据集中可能包含敏感字段，建议启用清洗选项，避免原始凭据、邮箱、IP 或目录路径直接进入训练集。

### 4.5 增加新的指标

如果你希望更全面地评价实验，可以加入以下指标：

- F1 / Precision / Recall
- 假阳性率 / 假阴性率
- 模型体积
- 冷启动时间
- 稳定性方差
- 不同数据切片上的分层表现

新增指标后，建议同时更新：

- CSV 输出
- JSON 汇总
- HTML 报告
- 文档中的解释口径

### 4.6 推荐的扩展实践

- 先小范围验证，再扩大实验空间
- 新模型先和强基线对比，再和全量模型族对比
- 固定随机种子，确保可复现
- 对稳定性敏感的候选模型，至少做一次重复实验
- 保持 `results.csv`、`best.json`、`coverage.json` 和命令行参数一一对应

### 4.7 一个实用的自定义实验清单

在提交自定义实验前，建议确认：

- [ ] 数据集已正确加载
- [ ] 模型 ID 已注册
- [ ] 参数网格已配置
- [ ] 覆盖率检查通过
- [ ] 结果目录命名清晰
- [ ] HTML 报告可正常打开
- [ ] 稳定性重复实验已完成
- [ ] 文档已同步更新

## 5. 常见问题

### 5.1 为什么不能只看准确率

因为在安全策略或命令拦截场景中，误拦截合法请求的代价很高。此时 ALLOW 通过率和准确率同等重要。

### 5.2 为什么要分稳定版和探索版

探索版用来快速扩展搜索空间，稳定版用来做重复实验验证。前者寻找上限，后者寻找可部署基线。

### 5.3 为什么要保留原始 CSV

因为后续可能需要：

- 重新画图
- 换评价口径
- 复核某个异常点
- 和新模型做横向比较

### 5.4 如何选择最终部署候选

优先选择满足以下条件的配置：

- holdout-comparable
- 验证准确率高
- ALLOW 通过率高
- 重复实验稳定
- 训练和推理成本可接受
