# eBPF 内核态 ML 模型可行性分析

## 🎯 目标

将机器学习模型压缩到 1MB 以内，编译为 eBPF 字节码，在内核态直接进行预测判断。

---

## 📊 可行性分析

### ✅ **可行的模型类型**

#### 1. **决策树 (Decision Tree)** - 最佳候选
- **内存占用**: ~10-50 KB (depth=8, 单棵树)
- **eBPF 实现**: 完全可行
- **性能**: 极快 (O(log n) 判断)
- **限制**: 
  - 深度 ≤ 20 (避免栈溢出)
  - 节点数 ≤ 1024

#### 2. **随机森林 (Random Forest, 少量树)**
- **内存占用**: ~200-500 KB (15-31 棵树)
- **eBPF 实现**: 可行
- **性能**: 快 (多棵树并行)
- **限制**:
  - 树数量 ≤ 50
  - 每棵树深度 ≤ 10

#### 3. **KNN (K-Nearest Neighbors, K≤5)**
- **内存占用**: ~500 KB - 1 MB (存储训练样本质心)
- **eBPF 实现**: 困难但可行
- **性能**: 中等 (需要距离计算)
- **限制**:
  - 只能存储质心/代表样本
  - K ≤ 5

#### 4. **线性模型 (Logistic Regression)**
- **内存占用**: ~1-2 KB (128 维权重)
- **eBPF 实现**: 完全可行
- **性能**: 极快 (单次点积)
- **限制**: 无

---

### ❌ **不可行的模型类型**

1. **深度神经网络**: 参数量太大 (>10 MB)
2. **Attention 机制**: 矩阵运算复杂度高
3. **N-Gram**: 需要 Map 结构 (eBPF 限制)
4. **大规模集成模型**: 内存超限

---

## 🔧 eBPF 技术限制

### 内核版本要求
- **最低**: Linux 5.10+ (CO-RE)
- **推荐**: Linux 5.15+ (更好的 Map 支持)

### eBPF 约束
1. **程序大小**: ≤1MB (编译后字节码)
2. **栈空间**: 512 字节
3. **指令数**: ≤100 万条
4. **Map 大小**: 可配置，但影响性能
5. **不支持浮点数**: 需要定点数模拟
6. **不支持循环**: 需要展开 (或使用尾调用)

---

## 💡 实现方案

### 方案 A: 轻量级决策树 (推荐)

**优势**:
- ✅ 内存占用最小 (~50 KB)
- ✅ 预测速度最快 (<1 μs)
- ✅ eBPF 实现简单
- ✅ 完全在内核态运行

**实现**:
```c
// 单棵决策树的 eBPF 实现
struct tree_node {
    u32 feature_idx;    // 特征索引
    s64 threshold;      // 阈值 (定点数 * 1000)
    u32 left_child;     // 左子节点索引
    u32 right_child;    // 右子节点索引
    s32 value;          // 叶节点值 (动作类型)
};

// BPF Map 存储树结构
struct {
    __uint(type, BPF_MAP_TYPE_ARRAY);
    __uint(max_entries, 1024);  // 最多 1024 个节点
    __type(key, u32);
    __type(value, struct tree_node);
} decision_tree SEC(".maps");
```

**内存估算**:
- 1 节点 = 24 字节
- 深度 8 = 最多 255 节点
- 总内存 = 255 × 24 = ~6 KB

---

### 方案 B: 随机森林 (15 棵树)

**优势**:
- ✅ 更高准确率
- ✅ 仍在 1MB 限制内
- ✅ 树并行评估

**内存估算**:
- 15 棵树 × 255 节点 × 24 字节 = ~90 KB
- 加上元数据 = ~100 KB

**实现**:
```c
// 多棵树的集成
#define NUM_TREES 15
#define MAX_NODES_PER_TREE 255

struct {
    __uint(type, BPF_MAP_TYPE_ARRAY);
    __uint(max_entries, NUM_TREES * MAX_NODES_PER_TREE);
    __type(key, u32);
    __type(value, struct tree_node);
} random_forest SEC(".maps");
```

---

### 方案 C: 混合架构 (最佳性能)

**Fast Path (内核态)**:
- ✅ 简单的规则匹配
- ✅ 轻量级决策树 (depth≤6)
- ⚡ 延迟 <1 μs

**Slow Path (用户态)**:
- 📊 复杂模型 (RandomForest, Attention)
- 🎯 高精度预测
- ⏱️ 延迟 ~50 μs

**触发条件**:
- Fast path 置信度 >90% → 直接决策
- Fast path 置信度 <90% → 回退到 slow path

## ⚠️ 技术挑战

### 1. 浮点数限制
**问题**: eBPF 不支持浮点数  
**方案**: 使用定点数 (s64, 精度 0.001)

```c
// 浮点 0.753 → 定点 753
#define FLOAT_TO_FIXED(f) ((s64)((f) * 1000))
#define FIXED_TO_FLOAT(i) ((double)(i) / 1000.0)
```

### 2. 循环展开
**问题**: eBPF 限制循环次数  
**方案**: 
- 树遍历不需要循环 (递归 → 展开)
- 森林投票使用展开循环 (#pragma unroll)

### 3. 栈空间限制
**问题**: 512 字节栈空间  
**方案**:
- 使用 BPF Map 存储中间结果
- 避免递归 (使用迭代)
