# Renew Desktop：Agent 识别与双范围名单

Desktop 入口：**防护与管理 → Agent 识别**（图标快捷栏中也有对应入口）。

## 两套策略互相独立

- **捕获范围（capture）**：事件经 eBPF 等来源进入后端并完成 Agent 上下文归因之后、语义分析与归档之前，决定该事件是否进入用户态事件库、持久化和前端事件流。捕获白名单为只捕获名单内的 comm 或 Agent 标签，捕获黑名单为排除名单内的对象。
- **监视范围（monitor）**：仅对已通过捕获策略的事件，决定是否进入语义告警及 loop/signal/research 分析队列。不监视并不删除事件：已捕获的原始摘要仍可浏览。监视名单不会覆盖 Wrapper 规则、LSM 安全执行或现有后端独立策略。
- **匹配规则**：对完整进程 `comm` 或已经归因的 `tag` 进行大小写不敏感的精确匹配，不使用正则、模糊匹配或 PID。一个名单最多 256 个条目，每个条目最多 128 字节。输入支持逗号/分号/换行分隔，保存时自动规范化、去重。
- **空名单行为**：黑名单空 = 全部通过；白名单空 = 无任何对象通过。两套名单初始均为空黑名单，保持历史行为。保存前确认白名单切换后的生效效果。
- **保存**：点击对应名单的保存按钮，只提交该名单编辑区的变化；另一名单未保存的草稿不会连带提交。UI 等待后端成功回复才更新生效状态，错误不会标记为成功。

## 后端契约

`GET /config/agent-scopes` 和 `PUT /config/agent-scopes`，响应/请求：

```json
{
  "capture": { "mode": "blacklist", "entries": ["bash"] },
  "monitor": { "mode": "whitelist", "entries": ["codex", "Claude Code"] }
}
```

GET 要求既有身份鉴权；PUT 还要求原有 `policyManagementEnabled` gate。名单持久化在 `~/.config/agent-ebpf-filter/agent-scopes.json`（以后端的真实用户目录解析为准）；更新经单个临时文件落盘后原子重命名，权限为 `0600`。

## 有意保留的边界

1. 捕获名单是**完成用户态归因后的事件接纳规则**，并不卸载、停止或重编译内核 eBPF 探针，也不保证减少内核 ringbuf 样本数量；系统调用采集的前段开销仍然存在。
2. 白名单无法复活上游已被 event-type/comm-disable 等既有规则屏蔽的事件。名单不对历史事件做回溯删除或重新分析。
3. 识别列表合并实时系统进程快照、注册命令及最多 1200 条近期事件摘要。同一命令的多个运行实例按 PID 区分；即使捕获白名单排除了该 Agent，只要实时进程快照仍能确定其身份，仍可在列表中选择并重新加入名单。系统流失联超过 15 秒时不继续将旧进程快照标为在线。页面只展示已登记、已被事件归因或确认为已知 Agent 的进程，而非宿主机所有进程。
4. 对于通过自定义数据源进入的事件，只有带有对应 `comm` 或已归因 `tag` 的事件才能被白名单匹配；没有这两种标识的事件不通过白名单。

5. 主事件归档/分析链路的名单策略不会覆盖独立 TLS capture store、历史录制/回放、LSM/cgroup 策略执行及外部插件自己的采集管线。这些路径有独立开关与权限边界，不应将本页面理解为全系统隐私开关。
