# 明镜高悬 · 常见敏感文件读写保护

## 功能定位

「路径权限」是 MyGo 原生桌面的文件访问控制页。这里的**读写限制是可执行的内核 BPF LSM 策略**，不同于 `ignoredPaths` 的事件降噪，也不同于「跟踪范围」的观察对象注册。

- 用户可以对一个**精确绝对文件路径**选择「阻止读取」「阻止写入」或「阻止读写」。
- BPF LSM 的 `file_open`、`file_permission`、`mmap_file` 和 `file_mprotect` 检查解析出的文件路径并根据读写权限位拒绝操作；内核 hook 拒绝通常以 `EACCES` 返回。
- 限制**全系统所有进程**，而非仅 Agent；不会默认生效。必须在「采集与能力」开启 `policy_management`，经过二次确认，确认内核返回的规则后才展示为生效。
- **目前仅精确文件，不支持目录递归、glob、符号链接别名策略。** 文件名不同、父路径不同均不匹配。内核路径超过 255 字节或无法由 `bpf_d_path` 解析时不能保证匹配，不能替代更完善的文件沙箱。
- 读取/写入操作的拒绝不等价于阻止 rename、unlink、chmod 和其它元数据操作；政策创建前已有的 mmap 也不会被撤销。这些都需要独立的内核 hook 覆盖。
- 仅对受支持的 Linux 内核与已成功挂载的 BPF LSM 生效，不能把 UI 配置成功当成对运行时内核行为的完整证明。

## 常见路径预设

预设列表含 SSH 私钥和配置、AWS / GCP / Kubernetes / GitHub CLI / Git / npm 凭据，以及若干 `/etc` 系统文件。默认只是**候选路径**，没有任何自动阻断。

`/etc/shadow`、`/etc/sudoers` 等文件与系统登录或提权相关。阻止读取可能导致系统服务不可用。UI 明确标记高风险，要求在执行前再次确认；建议优先在隔离测试机或虚拟机中验证，不建议在生产工作站直接禁用读取。

## 内核策略映射兼容性

复用现有 pinned `lsm_blocked_exec_paths` 映射的 `lsm_path_key` 和 `uint32` 值，避免升级时销毁原有策略。

| 位 | 作用 |
| --- | --- |
| 1 | 禁止执行（兼容旧策略） |
| 2 | 禁止读取 |
| 4 | 禁止写入 |

读写权限修改采用原值读-修改-写，并以互斥锁串行化，保留原有执行阻断位。状态接口 `GET /sandbox/lsm/status` 新增 `pathAccessRules`，返回用户设置的精确文件路径及两个布尔标志。`PUT /sandbox/lsm/path-access` 请求要求同时显式提供 `path`、`denyRead`、`denyWrite`；二者均为 false 时只撤销这两项，不触碰该路径执行阻断标志。API 仍同时要求鉴权、编译期 feature 与运行时策略管理 gate。

## 验证建议

1. 在隔离环境使用临时普通文件测试读取、写入、已打开文件描述符和 mmap 阻断。
2. 验证已有执行阻断规则未被读写规则覆盖，反向撤销亦然。
3. 确认无权限、LSM 不可用、路径输入无效时不会显示虚假的成功状态。
4. 核对默认关闭的预设没有在启动时擅自创建规则。

### 启用前的路径验证与高风险确认

新增规则要求文件已存在、为普通文件、且完整路径（包括父目录）不经过符号链接，否则明确拒绝启用，以防 BPF 内核真实路径与用户输入不一致。删除原始文件后仍允许通过原字符串路径撤销规则。硬链接、挂载别名与后续替换 inode 的情况不能仅凭精确路径断言完整覆盖。

阻止 `/etc/shadow`、`/etc/passwd`、`/etc/sudoers` 等关键认证文件读取时，除原确认操作外，还需要手动输入 `确认高风险`。

在支持 BPF LSM 的隔离 Linux 环境，可设置 `AGENT_ALLOW_LSM_PATH_SMOKE=1`，运行 `scripts/path-access-smoke.sh` 对临时普通文件验证内核拒绝读取、写入及规则撤销。不要对真实系统凭据执行烟测。
