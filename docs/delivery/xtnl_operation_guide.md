# 全国大学生计算机系统能力大赛 - 现场答辩操作与演示指南

本指南旨在为答辩现场的实机演示（Live Demo）提供标准化操作手册，确保演示过程顺畅，完美展示系统对于**“跨层数据关联”、“逻辑死循环检测”**与**“非侵入式加密流量截获”**等核心赛点的解决能力。

---

## 1. 演示环境准备

### 1.1 硬件与系统要求
* **操作系统**：Linux Kernel 5.15 及以上（必须启用 BPF LSM 和 cgroup v2）。
* **权限要求**：必须使用 `root` 或具有完整 eBPF 挂载权限的 `sudo` 账户运行。
* **依赖环境**：Go 1.26+、Bun（用于前端视图加载）、Python 3（用于运行模拟脚本）。

### 1.2 预检操作
在演示开始前 10 分钟，请先执行系统的底层支持预检，以确保环境无异常：
```bash
make os-enforcement-preflight
make os-enforcement-check
```
*注：如果现场环境网络不佳，建议提前下载所有需要的依赖并测试通过。*

## 2. 启动核心监控系统

在正式答辩开始时，向评委说明当前环境。
开启终端一（Terminal 1），启动整个 Agent eBPF Filter 的后端（内核态采集 + 分析引擎）与前端大屏：

```bash
# 建议在包含完整源代码的目录下执行
make dev
```
启动成功后，浏览器打开前端控制台：`http://localhost:5173`。

### 讲解要点：
> “评委老师好，现在我已启动了 Agent eBPF Filter 系统。大家可以看到前端大屏目前事件瀑布流处于静默监控状态。我们的 eBPF kprobes、tracepoints 甚至用于解密 HTTPS 流量的 uprobes 都已经以**非侵入式**的方法在操作系统后台挂载完毕。”

## 3. 运行多智能体并发模拟器

向评委介绍接下来将模拟的大语言模型异常行为场景。
开启终端二（Terminal 2），执行我们在 `scripts` 下准备的比赛专用测试脚本：

```bash
chmod +x scripts/xtnl_competition_demo.py
python3 scripts/xtnl_competition_demo.py
```

该脚本会在后台并发拉起 3 个互相交织的智能体（AI Agent）进程：
1. **Agent A**：发生模型幻觉，陷入逻辑死循环。
2. **Agent B**：试图读取系统密码和越权删除文件。
3. **Agent C**：日常正常的工作流干扰。

## 4. 大屏追踪与赛题亮点展示 (演示高潮)

在终端执行脚本后，立即切换回浏览器的前端控制台，按以下流程进行展示：

### 4.1 展示“跨越语义鸿沟”能力 (重点：40% 核心得分点)
- **操作**：打开 `AgentSight 视图` 或 `告警（Alerts）大盘`。
- **看点**：展示屏幕上弹出的警报信息。点击其中一条告警。
- **讲解语**：
  > “大家可以看到，这里产生了告警。请注意，我们不仅抓到了底层的 `unlink` 或者网络请求，我们的系统还通过 uprobes **非侵入式**截获了加密通道里的明文 Prompt（比如显示为 'Find the bug and fix it'）。我们将这条上层语义直接关联到了底层的资源浪费行为上，彻底跨越了**语义鸿沟**。”

### 4.2 展示“异常发现与因果匹配”
- **操作**：在 `Execution Graph (执行拓扑图)` 中筛选 `Agent A` 的进程。
- **看点**：展示高频的红线（网络外发与临时文件创建）。
- **讲解语**：
  > “在这个复杂的并发环境中，我们通过追踪 `agent_run_id` 剥离出了 Agent A 的进程树。系统判定出它结合了高频无意义的 API 调用与本地垃圾文件写入，所以准确定性它为**‘逻辑死循环’（RESOURCE_WASTING_LOOP）**，而不是正常的业务逻辑。”

### 4.3 展示“底层强制阻断” (加分项)
- **操作**：筛选 `Agent B` 的越权操作记录，查看文件读取状态。
- **看点**：展示试图访问 `/etc/shadow` 时，底层记录的返回值是 `EACCES (Permission Denied)`。
- **讲解语**：
  > “对于带有恶意的 Agent B 试图读取敏感文件或意外启动 Shell 时，我们的 BPF LSM 防护网在内核最底层就直接把它拒之门外了，应用层的任何欺骗手段都无法绕开这里的控制。”

### 4.4 展示“端侧低性能损耗” (< 5% 验证)
- **操作**：切换到 `System Health` 或通过自带的监控看板查看系统负载。
- **讲解语**：
  > “虽然我们做了这么多跨层的分析，但因为采用了 eBPF 的零拷贝 Ringbuffer，在刚才的多并发压测下，我们整个捕获组件的系统 CPU 和内存占用严格控制在了 **5%** 以下，是真正轻量级的生产可用底座。”

## 5. 常见问题应对 (Troubleshooting)

- **如果现场无外网**：
  脚本内部针对外网请求有超时处理（`try...except` 忽略报错），系统底层只要捕获到它**试图**发出 `connect/sendto` 系统调用，即可完成语义归因告警，不需要外网真实通畅。
- **如果现场不支持加载 BPF LSM**：
  系统会智能回退为**“仅告警模式”**。您仍可以在大屏中向评委展示准确识别出了“越权访问”意图，只需向评委说明当前演示机内核未启用 LSM 特性，但不影响异常检测评分。
- **如果评委质疑“明文提取”是否侵入**：
  可以直接展示 `backend/ebpf/agent_tls_capture.c` 源码中的 `SEC("uprobe/SSL_write")` 段落，证明这是完全在内核态利用动态插桩实现，未修改任何 OpenSSL 源码或重编译 Agent。
